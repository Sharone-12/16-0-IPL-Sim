--------------------------------------------------------------------------------
1. WHAT THE AUCTION IS
--------------------------------------------------------------------------------
A third game mode alongside Single Player Draft and Multiplayer Draft. 2-10
managers bid IPL-style, set by set, one player at a time, for an XI of exactly
11 (no bench). When the hammer falls on the last lot everyone proceeds into the
SAME league + knockout simulation the multiplayer draft uses.

HARD CONSTRAINT FROM THE USER, STILL IN FORCE:
  "this is a new feature dont touch the current multiplayer"
The MP draft flow (lobby.html, draft-mp.html, draft-mp.js) must keep behaving
exactly as it does. sim-mp.js and simulation.css ARE shared — changes there must
either be strictly additive or gated on `mpMode === "auction"`.

Entry points:
  index.html          .auction-glow button -> auction.html
  auction.html        lobby: create / join / waiting room (self-contained <style>)
  auction-room.html   the live auction (uses auction.css)
  auction-room.js     ~1200 lines, all auction logic
  auction_data.js     pure functions, UMD, no DOM/network — runs under Node
  sim-mp.js           league + knockouts, SHARED with the MP draft


--------------------------------------------------------------------------------
2. THE CENTRAL DESIGN IDEA
--------------------------------------------------------------------------------
The lot list is NEVER stored. Every client derives the identical ordered pool
from the CSVs via auction_data.js (same room settings in -> same lots out). The
only shared state is a pointer: which lot is live and what it is going for.

Same trick as the simulation, which seeds one RNG from the room id so every
client computes byte-identical match results from one shared `sim_round`.

Contention is always resolved by CONDITIONAL UPDATE, never by locking:
  - a bid lands only if it beats the stored price
  - a lot sells once, guarded by PRIMARY KEY (room_id, lot_index)
  - the pointer advances only from the index the mover actually saw
  - league setup is claimed by `status='auction' -> 'league_setup'` CAS

3. DATA
--------------------------------------------------------------------------------
ipl_auction_career_final.csv  322 hand-curated lots: Auction_Set, Tier,
                              calibrated OVR, Base_Price_Cr. THE user mapped
                              these by hand — do not recompute sets or prices.
                              Plus Role_Override / Batting_Order_Override (44
                              rows) — see below.

EVERY LOT USES THE PLAYER'S SINGLE HIGHEST-OVR SEASON, which is frequently NOT
the role they are known for. Rohit's peak is 2008, when he batted middle order;
Jadeja's is a 2019 season classed as a pure bowler (31% of his 267 matches).
Role_Override / Batting_Order_Override in the AUCTION csv correct the labels for
the auction only — buildCuratedPool prefers them over the master row, so the
draft and solo modes are untouched. Derivation rule:
  Batting_Order = matches-weighted modal over the last 8 PLAYED seasons
                  (career-wide modal keeps Rohit middle-order: he has 159
                  middle-order matches vs 122 opening, purely from debuting in
                  2008)
  Primary_Role  = career-wide modal, but All-Rounder wins if >=33% of career
                  matches were as one (a recency window demotes Pollard, Yuvraj
                  and Morris for bowling less late on — a worse error)
Overrides change eligibleSlots, so re-run the supply check for teams 2-10 after
touching them. R Ashwin is deliberately NOT overridden: he is Bowler/Lower Order
in every season bar a 2-match 2009, Bat_Rat mostly ~70. The all-rounder label is
his Test reputation, not his IPL output.

NOT MISSING, CONTRARY TO A REPORT: MA Starc is in the catalogue (Bowlers - B,
OVR 79). The 486 players outside it peak at OVR 83 with mostly <35 matches — no
prominent player is absent. Starc's curated 79 vs his master 2015 of 87 is what
buries him in Tier B.
ipl_master_calibrated.csv     3354 player-seasons, 808 distinct players. Source
                              of Bat_Rat / Bowl_Rat / Batting_Order / keeper /
                              nationality, and of the 486-player reserve.

TWO RATING SCALES, and this caused a real bug:
  lot.ovr      auction scale (the number on the bid card)
  lot.simOvr   master scale, ~5 higher (median delta 5, max 13)

The user's decision: the auction OVR is authoritative. finishAuction now writes
`simOvr: p.ovr` and shifts bat/bowl by the same delta via shiftRating(), so the
rating you bid for is the rating that plays. Do NOT "fix" this back — writing
master-scale simOvr means the sim DISPLAYS one number and PLAYS another.

Balance after that change (measured, 230 simulated squads):
  human auction XI  86.0 avg   |   bot 2026 franchise best-XI  79.9 avg

Money is integer LAKH everywhere (PURSE = 10000 = Rs 100 Cr, MIN_BASE = 50).
Only the display layer converts. Never use floats for purses.

Key constants:
  auction_data.js   PURSE 10000 · XI_SIZE 11 · MAX_OVERSEAS 4 · TOP_ORDER_SLOTS 7
  auction-room.js   LEAGUE_SIZE 10 · CLOCKS snappy/brisk/relaxed
  sim-mp.js         MP_LEAGUE_SIZE 10 · MP_REPLAY_STEP 5 · MP_PRESENCE_WINDOW_MS 60000

4. THE FLOW, END TO END
--------------------------------------------------------------------------------
auction.html      host creates (settings.mode='auction', clock, ratings, era)
                  -> host presses Start -> rooms.status='auction', purses seeded
auction-room.js   322 lots under the hammer. tick() runs every 120ms on every
                  client; whoever notices an expiry first resolves it.
                  finishAuction(): fillShortSquads, then each client writes ONLY
                  ITS OWN players.xi (see §6).
proceed()         CAS claim -> setUpLeague() -> rooms.status='league'
                  Everyone else follows via realtime (+ a polling fallback).
sim-mp.js         boots from players.xi, builds 10 teams, then a vote ladder:
                    -1  nobody started
                     0  whole 14-round league auto-plays, then the points table
                     1  Qualifier 1   } gated ONLY on the two humans in it
                     2  Eliminator    } bots never vote
                     3  Qualifier 2   } non-qualifiers spectate every scorecard
                     4  Final
                     5  Play Again    (every live human)

FIXTURES: 10 teams split into two groups of five off a STABLE id sort. Within
group home+away (8), cross-group once (5), plus the index-paired rival twice
(+1) = 14 each, 70 total, dealt into 14 matchdays of 5 by a true 1-factorisation
(mpPerfectSchedule). Top 4 by pts -> NRR -> wins -> team id go to the bracket.

5. SQL — ALL MIGRATIONS ARE RUN, NONE PENDING
--------------------------------------------------------------------------------
mp_schema.sql  mp_sim_sync.sql  mp_replay.sql  mp_presence.sql
mp_auction.sql  mp_auction_pause.sql  mp_cleanup.sql

All are idempotent. `alter publication ... add table` raises 42710 on a re-run
and ABORTS the rest of the script, silently skipping the replica identity
statements after it — every such call is guarded by a pg_publication_tables
check. Keep it that way.

The host-kick feature deliberately needs NO migration: it reuses players.status.

6. INVARIANTS YOU CAN BREAK WITHOUT NOTICING
--------------------------------------------------------------------------------
(a) BOT IDS MUST BE DERIVED, NOT RANDOM.
    `bot_${ROOM}_${seat}`. Random ids meant two managers clicking Proceed at the
    same moment each inserted 8 bots -> an 18-team league where only the first
    10 ids got fixtures, so both humans played 0 matches. This actually shipped.

(b) LEAGUE SETUP RUNS EXACTLY ONCE.
    It resets every sim_ready_step. A second client running it a moment later
    wipes votes already cast in the sim and stalls the room on 0/N.

(c) NEVER DELETE A players ROW MID-SEASON.
    Every client derives fixtures from the roster. Removing a row gives anyone
    who reloads a different league and desyncs the room. This is why "kick" sets
    status='kicked' instead: the manager keeps their TEAM, loses their VOTE.

(d) TWO CODE PATHS WRITE players.status AND WILL UN-KICK SOMEONE.
    finishAuction (own row) and setUpLeague's fill loop. Both now preserve
    'kicked'. If you add a third writer, preserve it there too.

(e) EACH CLIENT WRITES ONLY ITS OWN players.xi.
    It used to write everyone's, so the last writer's auto-assignment clobbered
    whatever batting order a manager had dragged. Absent managers are filled in
    by setUpLeague, which is the single CAS-claimed writer.

(f) A BID EXTENDS THE CLOCK, IT DOES NOT REPLACE IT.
    bumpedDeadline() = min(remaining + bump, open). Replacing meant bidding with
    5s left on a brisk clock moved it to 6s ("+1 second"), and the first bid on a
    relaxed 12s clock SHORTENED it to 8s.

(g) CSS: AUTHOR `display` BEATS THE [hidden] ATTRIBUTE.
    Any hideable element whose class sets `display` needs an explicit
    `.thing[hidden] { display: none }`. Missing this once left the SOLD popup on
    screen from page load, dimming the whole room.

(g2) STYLE COLUMNS + THE COMPOSITION MODIFIER ARE AUCTION-ONLY BY CONSTRUCTION.
    Batting_Hand / Bowling_Type / Bowling_Arm live in the AUCTION csv (312/322
    and 286/322 filled; blanks are deliberate — a wrong player is worse than an
    empty cell). They flow lot -> players.xi -> buildMpTeams.
    attackFactor() and handMixFactor() in sim-mp.js return EXACTLY 1 when the
    fields are absent, and drafted/bot XIs come from the master csv which has no
    such columns — so the draft and solo strengths are bit-identical (verified,
    not assumed). Do not "helpfully" default a blank style to Pace: that would
    silently start modifying the draft.
    Scale is deliberately asymmetric — worst attack -1.71 team OVR, best +0.29:
      monoculture (5 of one discipline) x0.952   4 spin + 1 pace x0.984
      typical 3 pace + 2 spin           x1.000   4 types + left-arm x1.008
    Variety/left-arm bonuses are GATED on the pace-spin split already being sane.
    Ungated, 4-spin-1-pace scored BETTER than 4-pace-1-spin, which inverted the
    whole intent.

(h) THE LOT RUNNING ORDER IS SEEDED, NOT SORTED.
    buildCuratedPool takes opts.seed (auction-room passes `${ROOM}:${season}`)
    and shuffles WITHIN each set. Without a seed it falls back to the old strict
    descending-OVR order, which is why the harnesses that omit it are unchanged.
    Two rules the shuffle must never break: sets stay CONTIGUOUS (nextSetIndex
    walks forward while setId matches) and stay in SET_ORDER sequence. And the
    seed must come from shared state only — anything client-local would give
    each browser a different lot list and desync the whole room.

(i) CSS: A GENERIC :hover OUTRANKS A VARIANT CLASS.
    `.btn:hover:not(:disabled)` (0,3,0) beats `.btn.accent` (0,2,0), so a hover
    rule that sets `background` silently strips a variant's fill. Bitten three
    times: the gold Create button, the active Pause button, the green "You hold
    the bid". Any variant must RESTATE background/color in its own :hover rule.

7. EVERY DEADLOCK ESCAPE (16 of them — see auction_deadlock.test.js)
--------------------------------------------------------------------------------
AUCTION
  - a lot nobody can bid on is auto-passed (shouldAutoPass)
  - an unparseable ends_at is cleared so the next tick opens a fresh clock
  - pause is host-only to SET; after PAUSE_GRACE_MS (2 min) ANY manager can
    resume, and after PAUSE_AUTO_MS (5 min) it resumes itself. Without this a
    host closing their tab mid-pause froze the room permanently.
  - removed managers cannot hold the "Move to Next Set" vote
  - the auction ends as soon as every squad is full
HANDOVER
  - a league_setup claim orphaned by a dead client is taken over after 20s
  - a failed setup rolls status back to 'auction' so Proceed is retryable
  - squads under 11 are completed before seats are counted
  - managers who never press Proceed are pulled in by realtime + polling
SIMULATION
  - stale heartbeats (>60s) drop out of every gate
  - status='kicked' drops out of every gate (covers idle-with-tab-open, which
    presence cannot see)
  - an all-bot knockout auto-advances after 5s
  - the host gets a "Waiting on ..." bar with a Remove button (auction rooms only)
  - an empty mpPlayers is NEVER read as "nobody needs to vote"
  - sim_ready_step values above the ladder are clamped (old rooms carry 14-18,
    which would satisfy every `>= target` and run the whole tournament unattended)

8. THE ABANDONED-MANAGER RULE (user asked for this explicitly)
--------------------------------------------------------------------------------
"what if they only pick 3 players and dip?" -> fillShortSquads completes them.
The user then said: "punish them harder they shd not reach top 6".

So completion now takes the WEAKEST legal player from a RESERVE built out of the
486 players who never made the 322-lot catalogue (buildReservePool: max OVR 83,
median 71, floor 55) — not the pick of the unsold premium lots.

Measured inside a real 6-manager auction, 12 runs each:
  quit after  0 signings -> XI avg 57.5      (bots average 79.9)
  quit after  3 signings -> XI avg 65.4
  quit after  6 signings -> XI avg 73.3
  played it out          -> XI avg 86.3
Every level is below the weakest bot franchise (MI, 77.4), so an abandoner
finishes bottom of the ten. Legality still guaranteed: even all ten managers
buying nothing yields ten legal XIs, keeper in the top 7, overseas cap held, no
duplicated player.

Known trade-off the user accepted ("idc as long as theres no deadlocks"): this
also catches the rare genuinely-stranded manager who bid properly but spent all
four overseas slots with no keeper.

auction_flow.test.js LIFTS THE REAL FUNCTIONS out of sim-mp.js and
auction-room.js by brace-matching the source and running them in a vm sandbox,
rather than restating the logic. If a function is renamed the harness throws
rather than silently testing nothing. Covers: OVR carry-over, seat trimming,
the fixture scheduler, drag-to-reorder, the bid clock, the kick, the pause
escape, abandoned squads.

auction_deadlock.test.js is a STRUCTURAL smoke check — it proves the escape code
is PRESENT, not that it works. Behavioural coverage lives in auction_flow.

Traps found while writing these, worth remembering:
  - a stub `shuffle` that reset its seed each call made all 50 scheduler retries
    identical and faked a scheduler failure
  - building a test squad by role picks 5 players who can only bat 1-3 (Buttler
    is a keeper who OPENS, Watson an all-rounder who OPENS) — assemble fixtures
    through A.canAdd instead
  - measuring an abandoned team against the UNTOUCHED pool said abandoning costs
    nothing (~90 either way); it must be measured inside a real auction
